# 仕様書（specs）

**コードを書く前に、ここに `.md` で仕様を書く。** AI に渡すのはこのファイル。

## なぜこの運用か

作るものが進まない最大の理由は「まとまった時間がない」ではなく、
**まとまった時間が来たときに"何を作るか"が決まっていない**こと。

だから、時間を種類で分ける。

| 時間の種類 | やること | 道具 |
|---|---|---|
| 細切れ（移動中・待ち時間） | 仕様を**言語化する**。鬼詳細まで詰める | スマホ。GitHub の Web エディタで直接編集 |
| まとまった時間 | AI に実装させ、受け入れ基準で**確認する** | PC |

考える作業に PC は要らない。ここを分離すると進む。

## 書き方

1. `_template.md` をコピーして `NNN-slug.md` を作る（例：`002-learning-log.md`）。
2. 番号は連番。既存の番号を再利用しない。
3. 冒頭の `Status` を更新する：`Draft` → `Ready`（実装してよい） → `Shipped` → `Archived`。
4. **`Ready` になっていない仕様は実装させない。**

## AI への渡し方

```
docs/specs/002-learning-log.md を読んで、この仕様の通りに実装して。
仕様に書かれていない判断が必要になったら、実装せずに質問して。
```

最後の一文が重要。AI に空白を埋めさせると、後で「なぜこうなっているか」が説明できなくなる。

## 仕様が曖昧だったと気づいたら

コードを直すのではなく、**仕様書を直してから作り直す**。
仕様書とコードがずれた状態を放置しない。ずれた瞬間にこの仕組みは無意味になる。
